# Keystone Architecture Decisions — v0.1

Approved baseline: **13 September 2026**

| ID | Topic | Accepted decision |
|---|---|---|
| D01 | Authority | Artifact-specific authority; contradictions are raised. |
| D02 | Documentation | Keep minimum durable knowledge. |
| D03 | Features | First-class but optional. |
| D04 | Feature docs | Boundary-focused map. |
| D05 | Tasks | `TASKS.md` index + individual task files. |
| D06 | ADRs | Lightweight structured metadata + readable sections/index. |
| D07 | Rules / skills | Separate mandatory constraints from procedures. |
| D08 | Model files | Thin adapters. |
| D09 | START | Deterministic context envelope. |
| D10 | CLOSE | Quality gate + durable knowledge classification. |
| D11 | Learning | Controlled promotion. |
| D12 | Learnings / traps | Separate linked concepts. |
| D13 | Review | Distinct independent code, architecture and context roles. |
| D14 | Reviewer input | Objective evidence package; no implementer private reasoning. |
| D15 | Validation | Deterministic structural checks + semantic agent review. |
| D16 | Index | Markdown authoritative; generated machine index disposable. |
| D17 | Budget | Target budget with priority tiers and explicit expansion. |
| D18 | CLI language | TypeScript/Node v0.1; protocol language-neutral. |
| D19 | Install | CLI initialization into target repository. |
| D20 | Mutation | Tiered permissions. |
| D21 | Compaction | Evidence-preserving consolidation. |
| D22 | Git | Task ID required for context-managed work; ADR ID when relevant. |
| D23 | Benchmark isolation | Clean clones/worktrees per condition. |
| D24 | Metrics | Balanced quality + efficiency scorecard. |
| D25 | v0.1 scope | Small working protocol + CLI; no external memory infrastructure. |
| D26 | Product name | Keystone; CLI command `keystone`. |

These decisions are frozen for v0.1. Material changes require a proposed ADR rather than silent
implementation divergence.
